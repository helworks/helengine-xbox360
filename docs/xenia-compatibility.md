(`superpowers/plans/2026-09-15-00-xenia-compatibility.md`). Every statement in
this report is tied to the pinned emulator revision and to a command that was
run on the recorded host; hypotheses are marked as such.

`run-probe.ps1` verifies the executable hash before every launch, writes each
run to its own folder under `build/logs/<run>/` (`command.txt`, `xenia.log`,
`summary.json`), closes the emulator window on timeout and only terminates the
process it started if the window close is ignored.

Two stock-emulator behaviours matter for unattended runs:

- On the first launch of a fresh storage root, `Emulator::Emulator`
  (`src/xenia/emulator.cc:146-165`) shows a Win32 Yes/No message box
  ("DISCLAIMER ... Would you like to open it?") before initialising anything
  and records the acknowledgement in persistent emulator flags. The run script
  answers "No" by clicking the dialog's own button; nothing else is automated.
- A host access violation raised while the emulator loads a title runs inside
  a window-procedure callback on the UI thread. Outside a debugger Windows
  swallows it, so a broken image produces no error, no launch and a live
  window. `tools/hostdbg.py` (Win32 debug loop, standard library only) exposes
  the exception with its address; see section 3.

| Item | Value |
|---|---|
| Toolchain | devkitPPC (GNU) inside the `devkitpro/devkitppc` Docker image |
| Image digest | `devkitpro/devkitppc@sha256:db8e39c73546d461d5606dc7dfed462a7d5957498502562e3b46769d02496cc1` (image created 2026-02-21) |
| Compiler | `powerpc-eabi-gcc (devkitPPC) 15.2.0`, target `powerpc-eabi`, defaults `-mcpu=750 -meabi -msdata=data -mbig-endian` |
| Linker/binutils | `GNU ld (GNU Binutils) 2.45.1`; emulations include `elf32ppc` |
| Licenses | GCC: GPL-3.0-or-later with the GCC Runtime Library Exception (`libgcc.a` is linked); Binutils: GPL-3.0-or-later. Both are build tools; the engine sources keep their own license. |
| Docker | Docker Desktop engine 29.6.1 on the host |
| Host scripting | Windows PowerShell 5.1, Python 3.11 (`C:\Program Files\Python311`) |

Flags used for guest code (recorded verbatim in `tools/build-probe.ps1`):

```
-mcpu=powerpc -m32 -mbig-endian -mno-eabi -msdata=none -mno-altivec
-mhard-float -mstrict-align -ffreestanding -fno-builtin -nostdlib
-fno-stack-protector -fno-asynchronous-unwind-tables -fno-pic -fno-common
-std=c11 -O2 -Wall -Wextra -Werror
```

Rationale: `-mcpu=powerpc` selects the generic 32-bit PowerPC instruction set
(no Gekko/Broadway paired-single instructions from the devkitPPC default
`-mcpu=750`); `-msdata=none` keeps the compiler off r2/r13 (Xenia's kernel
owns r13 for the KPCR, see section 2); `-mno-eabi` selects the SVR4 calling
convention (arguments in r3-r10, return in r3), which matches what the kernel
export shims expect for up to eight arguments.
